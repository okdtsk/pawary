# Pawlog Plan 5: PWA & Polish — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish v1. Make Pawlog an installable PWA per spec §8 — app shell precached, API GETs cached for offline reading with an "offline — showing saved data" indicator, photos cache-first, writes requiring connectivity with a friendly localized failure, a "new version — reload" update toast, real committed app icons, and a custom iOS install hint — then fold in every deferred review minor from Plans 3–4 (viewer-role gating on add surfaces, calendar/data seams, duplicate-create protection after photo failures, lightbox Escape, sequenced care undo, dismissal pruning, anomaly deep-link anchors, the worker's occurredAt bounds message, week-timeline pagination), and close with a whole-product wire-check, a permanent asset-serving test, and the final README pass.

**Architecture:** Everything builds on the merged Plans 1–4. The service worker is generated by `vite-plugin-pwa` (Workbox `generateSW` mode) configured entirely inside `app/vite.config.ts` — no hand-written SW file. The worker (Hono) is untouched except for ONE error-message string in `worker/src/routes/schedules.ts` and ONE new permanent test file; the existing `assets` binding in `worker/wrangler.jsonc` (directory `../app/dist`, SPA fallback, `run_worker_first: ["/api/*"]`) already serves whatever Vite emits, so `sw.js` / `manifest.webmanifest` / icons ship through the same pipeline, with `app/public/_headers` gaining `Cache-Control: no-cache` entries so SW updates are detected promptly. Frontend additions live in `app/src/features/pwa/` (UpdatePrompt, InstallHint), `app/src/lib/` (useOnline, errors), and targeted edits to existing files. Icons are REAL PNGs committed under `app/public/icons/`, rasterized once from a committed `paw.svg` by a one-off node script.

**Tech Stack:** New devDependencies: `vite-plugin-pwa` (app workspace) and `sharp` (root, used once by the icon script). Everything else unchanged: TypeScript, Hono 4, D1/R2, Vitest + @cloudflare/vitest-pool-workers; React 19, TanStack Query 5, Tailwind CSS 4, Vite 7.

**Spec:** `docs/superpowers/specs/2026-06-11-pawlog-design.md` (read §1 v1 boundary and §8 PWA/i18n/Offline before starting).

**Roadmap context:** This is plan 5 of 5 — the FINAL plan of the v1 build. Plans 1–4 are merged on `main`: full API (auth, pets, activities, photos, presets, export, schedules, care-status, insights, anomalies), full frontend (shell, add flow, calendar, log, settings, health tab, home slots), 182 worker tests + app unit tests green. The D1 schema is complete and FROZEN: no migrations, no schema edits of any kind in this plan. Deployment is explicitly out of scope (spec §1: "Local development only; deployment is a later step").

**Conventions used throughout (carried from Plans 1–4):**
- IDs are ULIDs via `newId()`; timestamps are epoch milliseconds (`Date.now()`).
- API responses: success `{ data }`, failure `{ error: { code, message } }` via `err()`.
- Frontend tasks verify with `npm run typecheck -w app && npm run build -w app`; tasks touching app unit-tested math also run `npm run test -w app`. Worker-touching tasks keep the full worker suite green: `npm run test -w worker && npm run typecheck -w worker`.

- Each task ends with a commit using the exact message given. Version numbers are minimums; never pin downward.
- The worker code diff in this whole plan is exactly: one string literal in `schedules.ts` (Task 7) and one new test file `worker/test/pwa-assets.test.ts` (Task 8). If you believe more worker changes are needed, STOP and report.

**Locked decisions for this plan (do not relitigate):**

| Decision | Choice | Why / spec note |
|---|---|---|
| SW generation | `vite-plugin-pwa` ≥1.0.0, Workbox **`generateSW`** mode, `registerType: "prompt"` | No custom SW logic needed in v1; prompt-mode + an update toast beats silent `autoUpdate` (a mid-session reload would eat a half-typed activity form). |
| API GET caching | **`NetworkFirst` with `networkTimeoutSeconds: 3`**, falling back to cache — NOT stale-while-revalidate | **Recorded deviation** from spec §8's "stale-while-revalidate" wording. SWR silently shows stale "today" dashboards (care due-badges, anomaly banners) even when online; NetworkFirst gives fresh-when-online, cached-when-offline, and the offline banner is the spec's "showing cached data" indicator. |
| Photo caching | `/api/photos/**` GET → **`CacheFirst`**, `maxAgeSeconds` 30 d, `maxEntries` 200, `purgeOnQuotaError` | Spec §8 "photos cache-first". Photo bytes are immutable per id (delete = new id on re-upload). |
| Auth endpoints | `/api/auth/**` → **`NetworkOnly`** | Never cache OAuth redirects / dev-login / logout. |
| Writes offline | `api()` client checks `navigator.onLine` before any non-GET and throws `ApiError(0, "offline", <localized message>)` — there is NO offline mutation queue | Spec §1/§8: "writes require connectivity in v1; offline mutation queue deferred". `navigator.onLine` is best-effort: a lying `onLine=true` just falls through to a normal fetch failure. |
| Offline read indicator | `useOnline()` (`navigator.onLine` + online/offline events via `useSyncExternalStore`) + a slim banner inside the Shell's sticky header | One global indicator instead of per-query staleness plumbing — honest and cheap. |
| App shell precache | `generateSW` precache of all built assets: `**/*.{js,css,html,svg,png,woff2}` (includes the self-hosted Fredoka/Nunito woff2 and the icons) | Spec §8 "app shell precached". |
| SPA navigation | `navigateFallback: "/index.html"`, `navigateFallbackDenylist: [/^\/api\//]` | Offline deep links (e.g. `/health`) must serve the shell; API URLs must never get HTML. |
| Manifest colors | `theme_color` **`#db7434`** (the design system's `--color-clay-500`), `background_color` **`#faf3e7`** (`--color-cream-100`, the body background) — and `index.html`'s stale `#f59e0b` theme-color meta is corrected to match | NOT the placeholder amber; checked against `app/src/index.css`. |
| Manifest lang | Static `"lang": "en"` | A static manifest cannot follow the device locale — **recorded deviation** from "lang per device"; all runtime UI is still locale-switched. |
| Icons | REAL committed PNGs in `app/public/icons/`: `icon-192.png`, `icon-512.png`, `icon-512-maskable.png`, `apple-touch-icon.png` (180) — rasterized from a committed `paw.svg` (the app's PawIcon mark, cream on a clay rounded square) by `scripts/make-icons.mjs` using a root `sharp` devDependency | One-off generation, deterministic, no binary mystery files. If `sharp` fails to install in the executor's environment, fall back to `@resvg/resvg-js` (variant included in Task 1). |
| Maskable / apple icons | Generated by flattening the same SVG onto a full-bleed `#db7434` square (rounded corners become invisible against the identical clay fill); paw content sits inside the central 80% safe zone | One SVG source, no second artwork. |
| SW/manifest serving | `app/public/_headers` gains `/sw.js` and `/manifest.webmanifest` blocks with `Cache-Control: no-cache`; **no CSP change** — the existing `default-src 'self'` covers `worker-src 'self'` so the SW registration is already allowed | Stale-SW lockout is the classic PWA footgun; verified against the current `_headers` and `worker/src/middleware/headers.ts` (identical CSP — parity maintained by changing neither). |
| Update UX | One-shot toast per session: "A new version of Pawlog is ready" + Reload action calling `updateServiceWorker(true)` | The toast auto-dismisses (6 s); the new SW activates on next full reload anyway. A persistent banner is post-v1 polish. |
| iOS install hint | Dismissible Card on Home shown only when: iOS Safari UA (incl. iPadOS-as-Mac via `maxTouchPoints`), NOT `display-mode: standalone` (or `navigator.standalone`), NOT previously dismissed (`localStorage` key `pawlog:iosInstallHint`) | Spec §8: "custom in-app iOS install hint (no prompt API on iOS Safari)". |
| Offline error surfacing | New `friendlyError(error, t)` helper (`app/src/lib/errors.ts`): ApiError code `offline` → its localized message; anything else → `t.errors.title`. Applied to the toast paths this plan already touches; `ActivityForm` already surfaces `ApiError.message` | Keeps every touched write path saying "you're offline" instead of a generic error. |
| B2 old-month invalidation | `useUpdateActivity(petId, id, previous?)` — the **caller passes the pre-edit activity** (`ActivityForm` already holds `existing`); no `onMutate` context plumbing | The data is already in hand at the only call site; mutation context would be indirection for nothing. |
| B9 week timeline | `useActivitiesRange` follows `nextCursor` for up to **3 pages of 200 (cap 600 activities)** — implemented, not just documented | A 7-day window over ~30 logs/day is ~210 rows; 200 silently truncated Sundays. 600 is far beyond family usage; beyond it we truncate (recorded). |
| B8 message | `"occurredAt must be within the last 7 days or up to 1 hour ahead"` | The code allows `[now − 7 d, now + 1 h]`; the old message omitted the future allowance. `schedule-complete.test.ts` asserts only status 400 — no test pins the string, none need updating. |
| Anomaly deep links | Home banners link to `/health#<rule>`; HealthTab chart cards get `id`s — `weight_drift` → weight card, `quiet_day` → intake card, `toilet_trouble` → toilet card, `symptom_streak` → timeline card — and `scrollIntoView` fires once per hash after charts load | Spec §7 "deep links to charts", made per-rule. |
| Root test order | Root `npm test` already builds the app before worker tests — after Task 1, `app/dist` therefore always contains `sw.js`/manifest when the worker suite (incl. the new Task 8 test) runs | Running `npm run test -w worker` standalone requires a prior `npm run build -w app`; that was already true (assets binding) and stays documented in the README. |

- [ ] **Step 2: Create `scripts/make-icons.mjs`**

```js
// One-off icon rasterizer: app/public/icons/paw.svg → committed PNGs.
// Run with: npm run icons   (requires the root `sharp` devDependency)
import { mkdir } from "node:fs/promises";
import path from "node:path";
import { fileURLToPath } from "node:url";
import sharp from "sharp";

const ROOT = path.dirname(fileURLToPath(import.meta.url));
const ICONS = path.join(ROOT, "..", "app", "public", "icons");
const SVG = path.join(ICONS, "paw.svg");
const CLAY = "#db7434";

async function main() {
  await mkdir(ICONS, { recursive: true });

  // Standard icons keep the transparent rounded corners.
  await sharp(SVG).resize(192, 192).png().toFile(path.join(ICONS, "icon-192.png"));
  await sharp(SVG).resize(512, 512).png().toFile(path.join(ICONS, "icon-512.png"));

  // Maskable + apple-touch are flattened onto full-bleed clay so OS masks
  // and iOS's forced-opaque corners never reveal gaps.
  await sharp(SVG)
    .resize(512, 512)
    .flatten({ background: CLAY })
    .png()
    .toFile(path.join(ICONS, "icon-512-maskable.png"));
  await sharp(SVG)
    .resize(180, 180)
    .flatten({ background: CLAY })
    .png()
    .toFile(path.join(ICONS, "apple-touch-icon.png"));

  console.log("icons written to", ICONS);
}

main().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
```

```js
import { readFile, writeFile } from "node:fs/promises";

async function render(size, background) {
  const svg = await readFile(SVG, "utf8");
```

```tsx
import { useEffect, useRef } from "react";
import { useRegisterSW } from "virtual:pwa-register/react";
import { useToast } from "../../components/Toast";
import { useT } from "../../i18n";

/**
 * Registers the service worker (registerType: "prompt") and shows a one-shot
 * "new version is ready" toast with a Reload action. In `vite dev` the
 * virtual module no-ops (devOptions are not enabled), so this renders inert.
 */
export function UpdatePrompt() {
  const t = useT();
  const toast = useToast();
  const announced = useRef(false);
  const {
    needRefresh: [needRefresh],
    updateServiceWorker,
  } = useRegisterSW();

  useEffect(() => {
    if (!needRefresh || announced.current) return;
    announced.current = true;
    toast.show(t.pwa.updateReady, {
      action: {
        label: t.pwa.reload,
        onClick: () => void updateServiceWorker(true),
      },
    });
  }, [needRefresh, t, toast, updateServiceWorker]);

  return null;
}
```

```ts
function subscribe(onChange: () => void): () => void {
```

```ts
export class ApiError extends Error {
  constructor(
    public status: number,
    public code: string,
    message: string,
  ) {
    super(message);
    this.name = "ApiError";
  }
}

let csrfToken: string | null = null;

export function setCsrfToken(token: string): void {
  csrfToken = token;
}

let offlineWriteMessage = "You're offline — this can't be saved until you reconnect";

/** Localized by I18nProvider whenever the locale resolves/changes. */
export function setOfflineWriteMessage(message: string): void {
  offlineWriteMessage = message;
}

export async function api<T>(path: string, init: RequestInit = {}): Promise<T> {
  const headers = new Headers(init.headers);
  const method = init.method ?? "GET";
  if (method !== "GET") {
    // Writes require connectivity in v1 (spec §8) — fail fast and friendly.
    if (!navigator.onLine) {
      throw new ApiError(0, "offline", offlineWriteMessage);
    }
    if (csrfToken) headers.set("X-CSRF-Token", csrfToken);
    if (init.body && !(init.body instanceof FormData)) {
      headers.set("Content-Type", "application/json");
    }
  }
  const res = await fetch(path, { ...init, headers });
  const body = (await res.json().catch(() => null)) as
    | { data?: T; error?: { code: string; message: string } }
    | null;
  if (!res.ok) {
    throw new ApiError(
      res.status,
      body?.error?.code ?? "unknown",
      body?.error?.message ?? "Request failed",
    );
  }
  return body!.data as T;
}
```

```ts
/**
 * All activities in [from, to] (inclusive) — calendar ranges, "today so far".
 * Follows nextCursor for up to 3 pages of 200 (cap 600): a 7-day week view
 * can exceed one page; beyond 600 rows the tail is silently truncated.
 * `enabled: false` keeps closed sheets from issuing throwaway 0..0 queries.
 */
export function useActivitiesRange(
  petId: string,
  from: number,
  to: number,
  opts?: { enabled?: boolean },
) {
  return useQuery({
    queryKey: keys.activitiesRange(petId, from, to),
    enabled: opts?.enabled ?? true,
    queryFn: async () => {
      const items: ActivityListResponse["items"] = [];
      let cursor: string | undefined;
      for (let page = 0; page < 3; page++) {
        const res = await api<ActivityListResponse>(
          listPath(petId, { from, to, limit: 200, cursor }),
        );
        items.push(...res.items);
        if (!res.nextCursor) break;
        cursor = res.nextCursor;
      }
      return items;
    },
  });
}
```

```tsx
  photoId,
  onClose,
  closeLabel,
}: {
  photoId: string;
  onClose: () => void;
  closeLabel: string;
}) {
  // The lightbox never holds focus, so a React onKeyDown would not fire —
```

- [ ] **Step 1: `useCompleteWithUndo.ts` — full replacement (sequence the undo, surface failures)**

Today the undo fires DELETE and PATCH concurrently and ignores DELETE failures (a failed DELETE + successful PATCH would resurrect the due item while keeping the logged activity). Sequence them and toast on failure:

```ts
import type { ScheduleResponse } from "@pawlog/shared";
import { useDeleteActivity } from "../../api/activities";
import { useCompleteSchedule, useUpdateSchedule } from "../../api/schedules";
import { useToast } from "../../components/Toast";
import { useT } from "../../i18n";
import { deviceTzOffsetMin } from "../../lib/dates";
import { friendlyError } from "../../lib/errors";

/**
 * Complete + undo, used by both the Health tab and the Home care card.
 * Undo is exactly (locked decision, Plan 4): soft-DELETE the activity the
 * completion created, THEN PATCH the schedule's nextDueAt/active back to the
 * values it had before completing — sequenced, so a failed delete never
 * resets the schedule while the logged activity survives.
 */
export function useCompleteWithUndo(petId: string): {
  complete: (schedule: ScheduleResponse) => void;
  isPending: boolean;
} {
  const t = useT();
  const toast = useToast();
  const completeMut = useCompleteSchedule(petId);
  const removeActivity = useDeleteActivity(petId);
  const updateSchedule = useUpdateSchedule(petId);

  const complete = (schedule: ScheduleResponse) => {
    completeMut.mutate(
      { id: schedule.id, input: { tzOffsetMin: deviceTzOffsetMin() } },
      {
        onSuccess: (res) => {
          toast.show(t.care.completed(schedule.name), {
            action: {
              label: t.care.undo,
              onClick: () => {
                void (async () => {
                  try {
                    await removeActivity.mutateAsync(res.activity.id);
                    await updateSchedule.mutateAsync({
                      id: schedule.id,
                      input: {
                        nextDueAt: schedule.nextDueAt,
                        active: schedule.active,
                      },
                    });
                    toast.show(t.care.undone);
                  } catch (error) {
                    toast.show(friendlyError(error, t), { tone: "danger" });
                  }
                })();
              },
            },
          });
        },
        onError: (error) =>
          toast.show(friendlyError(error, t), { tone: "danger" }),
      },
    );
  };
  return { complete, isPending: completeMut.isPending };
}
```

- [ ] **Step 2: `dismissals.ts` — full replacement (prune prior-day keys on write)**

Dismissal keys are day-scoped, so without pruning they accumulate forever. The day suffix is always the trailing 10-char `YYYY-MM-DD` (symptom names may themselves contain `:`, so match the suffix, not a split):

```ts
import type { Anomaly } from "@pawlog/shared";

/**
 * Dismissals live client-side, scoped to pet + rule (+ symptom name for
 * symptom_streak) + household day — a new day re-evaluates, which is how
 * "reappear only on new triggering data" (spec §7) works in practice.
 */
const PREFIX = "pawlog:anomaly:";

function storageKey(petId: string, anomaly: Anomaly, day: string): string {
  const sub = anomaly.rule === "symptom_streak" ? anomaly.params.name : "";
  return `${PREFIX}${petId}:${anomaly.rule}:${sub}:${day}`;
}

/** Drop every dismissal not scoped to `today` — keys are day-suffixed. */
function pruneOldDismissals(today: string): void {
  try {
    const stale: string[] = [];
    for (let i = 0; i < localStorage.length; i++) {
      const key = localStorage.key(i);
      if (key?.startsWith(PREFIX) && !key.endsWith(`:${today}`)) stale.push(key);
    }
    for (const key of stale) localStorage.removeItem(key);
  } catch {
    // storage unavailable — nothing to prune
  }
}

export function isDismissed(petId: string, anomaly: Anomaly, day: string): boolean {
  try {
    return localStorage.getItem(storageKey(petId, anomaly, day)) !== null;
  } catch {
    return false; // storage unavailable → banner simply shows
  }
}

export function dismissAnomaly(petId: string, anomaly: Anomaly, day: string): void {
  pruneOldDismissals(day);
  try {
    localStorage.setItem(storageKey(petId, anomaly, day), "1");
  } catch {
    // private mode etc. — the banner reappears next render, acceptable
  }
}
```

## Spec deviations encoded in this plan (intentional)

1. **API GET caching is NetworkFirst (3 s timeout → cache), not stale-while-revalidate** — spec §8 says SWR. SWR silently serves stale "today" data (care badges, anomaly banners) even when online; NetworkFirst is fresh-when-online, cached-when-offline, and the global offline banner is the spec's "showing cached data" indicator. Revisit if p95 API latency ever approaches the timeout.
2. **Manifest `lang` is static `"en"`** — a static manifest cannot follow the device locale; all runtime UI remains fully locale-switched. (Per-locale manifests are post-v1 polish.)
3. **`theme-color` corrected to `#db7434`** — `index.html` carried a pre-design-system placeholder (`#f59e0b`); the manifest and meta now use the real clay-500 from `index.css`.
4. **Root `sharp` devDependency added for a one-off script** — the icon PNGs are committed; `sharp` is never in any build or test path. Fallback `@resvg/resvg-js` documented in Task 1.
5. **Update toast is one-shot per session** and auto-dismisses after ~6 s — a missed toast just means the update applies on the next natural reload. A persistent update banner is post-v1.
6. **Week timeline caps at 600 activities** (3 pages × 200) — beyond that the tail is silently truncated; far past family-scale usage, recorded here for honesty.
7. **`occurredAt` bounds message reworded** (worker) — behavior unchanged; the message now matches the `[now − 7 d, now + 1 h]` window the code enforces.
