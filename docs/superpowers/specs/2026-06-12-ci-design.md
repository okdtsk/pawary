# GitHub Actions CI/CD — Design

**Date:** 2026-06-12
**Status:** Approved
**Scope:** One workflow: typecheck + full test suite on every PR and push to main; pushes to main additionally apply pending D1 migrations and deploy the worker to production. Post-v1 Phase 2.

## 1. Context

Deploys are currently manual from a laptop (`wrangler deploy --env production` from `worker/`, with `wrangler d1 migrations apply pawary --remote --env production` when migrations are pending). The repo is an npm-workspaces monorepo (shared/worker/app) on GitHub (`okdtsk/pawary`, PR #1 merged). Root scripts: `npm run typecheck` (3 workspaces), `npm test` (builds app, worker vitest via workers pool, app vitest), `npm run build`.

## 2. Decisions (user-approved)

| Decision | Choice |
| --- | --- |
| Scope | **Tests + auto-deploy on main** (PRs: tests only) |
| Workflow file | Single `.github/workflows/ci.yml`, jobs `test` and `deploy` (deploy `needs: test`, push-to-main only) |
| Migrations | `wrangler d1 migrations apply pawary --remote --env production` runs before every deploy (idempotent, no-op when none pending) |
| Auth | `CLOUDFLARE_API_TOKEN` GitHub Actions secret (user-created; never pasted into chat); `CLOUDFLARE_ACCOUNT_ID` as plain env (`15e92cf7a2d85b77cd798213277382d2`, not a secret) |
| Token-leak hardening (user concern, 2026-06-12) | Cloudflare API has no OIDC federation, so a stored token is unavoidable for CI deploys. Mitigations: (1) token env is **step-level** on the two wrangler steps only — `npm ci`/build never see it (supply-chain exfiltration is the realistic vector); (2) secret stored in a GitHub **`production` environment** branch-restricted to `main`; (3) actions SHA-pinned; (4) token created with **90-day TTL** + minimal scope (Workers Scripts: Edit, D1: Edit), so a silent leak self-expires. Workers Builds (token-less) was considered and declined: weaker test gating and dashboard-held pipeline config. |
| Node | 22 (vite 7 floor), `actions/setup-node` with npm cache, `npm ci` |
| Concurrency | `concurrency: deploy-production` on the deploy job — no overlapping deploys; older queued deploys cancelled in favor of the newest |
| Local deploys | Remain possible (README keeps the commands) but CI becomes the normal path |

## 3. Workflow shape

- `on: push` (branches: main) + `pull_request` (branches: main).
- `test` job: checkout → setup-node 22 + npm cache → `npm ci` → `npm run typecheck` → `npm test`.
- `deploy` job: `if: github.event_name == 'push' && github.ref == 'refs/heads/main'`, `needs: test`, concurrency-gated. checkout → setup-node → `npm ci` → `npm run build` → migrations apply → `wrangler deploy --env production` (both from `worker/`, `npx wrangler` pinned by the lockfile, authed via env).

## 4. User-only step

Create a Cloudflare API token (custom token: Account → Workers Scripts: Edit + D1: Edit, scoped to the account) and store it: `gh secret set CLOUDFLARE_API_TOKEN` (interactive paste in the user's terminal). The `test` job is green without it; the `deploy` job fails with a clear auth error until the secret exists.

## 5. Out of scope

Preview deployments for PRs, release tagging, branch protection rules, secret rotation, CI for the (nonexistent) lint step.
